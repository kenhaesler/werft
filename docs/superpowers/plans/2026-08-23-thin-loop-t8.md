# Thin Loop T8 Implementation Plan — evidence collection minimum

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Implement thin-loop task T8 (#25): after every attempt teardown the manager collects the run's evidence — `workspace/.werft-artifacts/`, `workspace/playwright-report/`, `workspace/test-results/`, the full `outputs/` tree (`log.jsonl` retained), and subnet-filtered egress log lines — into `{artifacts_root}/{run_id}/artifacts/`, writes one `artifacts` row per file, records what was dropped as a run event, and stops claiming new runs at 90% disk usage with an alert. One PR, green CI.

**Architecture:** T7 already shipped the hard halves: the hostile-tree-safe collector (`runner/collect.py`, caps + largest-first eviction, fully unit-tested), the `artifacts` table (`0001_spine.py:295-309`), the hardened list/serve endpoints (`api/routes.py:326-355,426-489`), and the dashboard artifact listing. **Tech Stack:** Existing manager stack (Python 3.14, FastAPI, SQLAlchemy 2 async + asyncpg, structlog, pytest 9 + pytest-asyncio auto, testcontainers) and the Svelte 5 dashboard. **No new runtime dependency. No new Alembic migration (the `artifacts` table exists). No import-linter contract change. No new API endpoint. No new `AlertSink` method. No new `run_events.event_type`.**

**Spec:** `/SPEC.md` §8 (evidence), §4.2/§4.3 (runner filesystem trust model), §9 (closed alert set), §10 (deployment seams). Issue #25 is the acceptance floor. ## Behavioral decisions (locked here so tasks do not re-litigate)

- **D1 — One budget, one sort, all sources.** The 100 MB cap and largest-first eviction are per **run**, spanning every source tree in one pass. `collect_trees` scans all sources first, then sorts the merged candidate list globally. Per-tree sequential calls would privilege earlier trees and let walk order decide survival — exactly what `collect.py`'s docstring forbids.
- **D2 — Collected paths are prefixed by source**: `werft-artifacts/…`, `playwright-report/…`, `test-results/…`, `outputs/…`, `egress/…`. The prefix is the `Artifact.path` prefix and the on-disk layout under `{artifacts_root}/{run_id}/artifacts/`. A missing source directory contributes nothing (an `os.walk` over a nonexistent root yields no entries — no error, no dropped entry).
- **D3 — `log.jsonl` is subject to the caps like every other file.** SPEC §8's "retained, full, by default" contrasts with redaction/pruning, not with the caps bullet that immediately follows it; a transcript exceeding 25 MB is dropped **and recorded**, which is the spec's own preference ("evidence that says 'truncated here'"). The adapter's transcript is additionally bounded upstream by `log_tail_bytes` reads. No exemption code path.
- **D4 — Collection runs on every teardown, idempotently, and the cap is attempt-aware.** Both teardown paths call it; a re-collection (retry attempt, sweep after driver crash) overwrites files and upserts rows via `ON CONFLICT (run_id, path) DO UPDATE SET bytes = excluded.bytes, collected_at = now()`. No sentinel file, no "already collected" state to rot. The 100 MiB cap is per **run across attempts**: a pass receives a map of what already exists under the dest dir and its cap check runs against the *effective* post-copy total — a candidate that overwrites an existing file is charged only its size **delta**, so the routine retry re-collection is never falsely dropped as `total_cap`, while genuinely new evidence from a later attempt still lands against whatever headroom remains.
- **D5 — The evidence event is always written, one per collection pass**: `event_type="dispatch"`, payload `{"phase": "artifacts", "collected": n, "bytes_total": N, "truncated": bool, "dropped": [{"path", "reason", "bytes"}, … first 100]}`. "What was dropped is recorded as an event" (SPEC §8) — and the collected count makes the no-drop case auditable too. The dropped list is bounded at 100 entries with a `"dropped_elided": k` key when longer (a hostile tree can produce unbounded drop entries; the event row must stay bounded). `Artifact.event_ref` stays NULL (SPEC §8 defers linkage).
- **D6 — Egress attribution is by source-IP-in-subnet, format-agnostic.** The manager knows the run's network (`werft-net-{run_id}`); before the network is removed it reads the network's IPAM subnets. A log line belongs to the run iff any whitespace-separated token parses as an IP address inside one of those subnets. This works for squid native format and any sane dns-guard log without parsing either format — T9 configures the services; T8's filter doesn't care. If T9's formats defeat token matching, the filter is one function to revise.
- **D7 — Egress collection is a silent no-op until T9 deploys.** Two new settings, `squid_access_log` and `dns_guard_query_log`, both default `""`. Empty setting, missing file, unreadable file, non-regular file, or no captured subnets ⇒ skip that source (debug log only, no dropped entry, no alert — absence of T9 is not an incident).
- **D8 — Egress reads are bounded from the tail.** The shared access log can be arbitrarily large; the filter seeks to `max(0, size − 32 MiB)` and scans forward, discarding the first partial line. Matched output is capped at 25 MiB (`MAX_FILE_BYTES`); hitting that cap truncates the *front* (oldest lines dropped first, the run's most recent egress is the detection stream that matters) and is recorded via the normal `too_large`-style accounting — see Task 3 for the exact rule. Filtered files are staged into `{run_dir}/egress/` (manager-owned, never mounted) and swept up by `collect_trees` like any other source, so caps, rows, and events stay uniform (D1).
- **D9 — Disk gate: fail-open, edge-triggered alert, dispatch-only.** `_sweep_disk_threshold` runs first in `tick_once`, computes `used/total` of `settings.artifacts_root` via `shutil.disk_usage`, sets `self._disk_over`; `_sweep_dispatch` returns immediately when set (claims stop; queued rows simply wait — no state change, no park). The alert fires on the rising edge only, re-arming when usage falls below threshold (an every-15s ntfy ping is operator abuse). If `disk_usage` raises (path missing on a dev box), log a warning and treat as not-over — a broken probe must not halt the factory. Threshold is `disk_threshold_percent: float = 90.0`.
- **D10 — Dashboard downloads go through `api()`-style fetch with the bearer token, then a Blob object-URL click** — a plain `<a href>` cannot carry the Authorization header. No token in the URL, ever.
- **D11 — Collection failures are logged, never fatal, and never block teardown.** The wrapper around the whole evidence pass catches `Exception`, logs `evidence_collection_failed` with the run id, and lets teardown continue to secret scrub — the secrets scrub is more important than the evidence.

```python
@dataclass(frozen=True)
class TreeSource:
    src_dir: str
    dest_prefix: str  # non-empty, no slashes at the edges, e.g. "outputs"

def collect_trees(
    sources: list[TreeSource],
    dest_dir: str,
    *,
    max_total_bytes: int = MAX_TOTAL_BYTES,
    max_file_bytes: int = MAX_FILE_BYTES,
    existing: dict[str, int] | None = None,   # prefixed rel_path -> bytes already at dest (D4)
) -> CollectionReport
```

  All `rel_path`s in the report (artifacts **and** dropped) carry the source's prefix (`f"{dest_prefix}/{rel}"`, forward slashes — normalize `os.sep` so `Artifact.path` is portable and matches the serving route's `{artifact_path:path}` semantics). `collect_outputs` keeps its exact current behavior (its tests are the proof).

  Cap accounting with `existing` (D4): the copy loop tracks `effective_total`, starting at `sum(existing.values())`; for each candidate, `prospective = effective_total − existing.get(rel_path, 0) + size`; drop as `total_cap` iff `prospective > max_total_bytes`, else copy and set `effective_total = prospective` (and drop the path from the working copy of `existing` so it isn't credited twice). `report.bytes_total` stays what it is today: bytes **written by this pass**.
