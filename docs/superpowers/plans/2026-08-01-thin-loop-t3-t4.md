# Thin Loop T3+T4 Implementation Plan — capable runner, Claude Code adapter

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Implement thin-loop tasks T3 (#20, capable runner: image build, lifecycle, hardening) and T4 (#21, Claude Code adapter and usage reader) per `/SPEC.md` v1.0 §4 and §5, each landing as its own PR with green CI.

**Architecture:** T3 builds the runner plane in `werft/runner/`: the create-body builder (a pure function of three enumerated components — the highest-value component in the system), a minimal async Docker Engine API client over an injected httpx transport, per-run network + container lifecycle driven by the `die` event, and the host-side artifact reader that never traverses non-regular files. T4 builds `werft/contracts/` (task.json / result.json, shared verbatim by manager and adapter), `werft/providers/claude/` (argv+env builder and the outcome classifier), and `runners/adapter/` (the in-container PID-1 runtime).

**Tech Stack:** Existing manager stack (Python 3.14, pydantic 2.13, httpx 0.28.1, pytest 9) + Docker Engine API v1.52 (Docker CE 29.6.2). No new runtime dependencies.

|---|---|---|

Quoted from SPEC (issue bodies are index entries, not the spec):

- **§4.2, the three-component rule:** "The create-body is built from three components [CD M1/M3/M6]: a `BASE` dict that never varies; an enumerated **per-run computed component** (container name, `NetworkMode` = the run's network, `Dns` = that network's dns-guard address, mount source paths); and a closed, typed per-project delta — permit **columns, not rows**. The body test asserts byte-equality on BASE, key-enumeration on the per-run component (no other key may ever appear there), schema on the delta, and explicit negative assertions."
- **§4.2 BASE (verbatim):** `ReadonlyRootfs=false`; `User` absent; `CapDrop=["ALL"]`; `CapAdd=<minimum empirically tested set>`; `SecurityOpt=["no-new-privileges:true"]`; default seccomp; SELinux labeling on (`:Z` workspace); `Privileged=false`; no host `{Pid,Ipc,Network,Cgroup}Mode`; no `Devices`; no `VolumesFrom`; no Docker socket; no published ports; no `ExtraHosts`; `PidsLimit=4096`; `ShmSize=1g`; `Memory`/`NanoCpus` capped per project config; tmpfs `/tmp`.
- **§4.2 mounts (verbatim):** "Mounts: workspace rw :Z; outputs dir rw :z (manager-readable, see §4.3); task.json ro; secrets/ ro directory; nothing else"
- **§4.1:** "One base image per project, **built on the VM by Werft** from a Werft-owned, human-authored Dockerfile… Digest-recorded on each run… **No agent-authored bytes ever enter an image build** [CD M4]; agents mutate the running container, never the image."
- **§4.3 completion:** "container `die` event (Docker events stream + reconciliation inspect; never blocking `wait`, never log content) + inspected exit code + `result.json`. Exit codes: `0` contract fulfilled (result.json written, valid); `2` CLI unstartable; `4` workspace/git failure; `5` result serialization failure; anything else = adapter crash."
- **§4.3 enforcement:** "**Enforcement is manager-side.** A root agent can kill or patch the in-container adapter, so the run ceiling (90 min default), tree-kill, and teardown are enforced by the manager via the Docker API; in-container redaction is best-effort only." And: "Host-side readers never traverse non-regular files: `lstat`, `followlinks=False`, running-total cap — never `cp -r`/`rsync -a`/`tar -C` [CD M8]."
- **§4.3 SELinux split:** "the **workspace** is `:Z` (private to the runner); the run's **outputs directory** (`result.json`, `log.jsonl`, artifacts) is a separate mount with the shared container label (`:z`) so the containerized manager can read it after exit."
- **§4.4 credentials:** per-run installation token attenuated to `contents: write` on one repo, delivered via `GIT_ASKPASS` file in the **ro secrets directory**, re-minted by rename before expiry, revoked at teardown. "Redaction handles both `ghs_` token formats (36-char and `ghs_APPID_JWT` long form) **by exact value, not regex shape**." Provider credential is manager-held, mounted ro.
- **§5 invocation:** "`claude -p` with `--output-format stream-json` piped to `log.jsonl`, final envelope parsed for `result.json`. **Never `--bare`** (mutually exclusive with the OAuth token and discards `CLAUDE.md` — [BP§15.3]); Werft context injected via `--append-system-prompt-file`." Model is "a config value per project/work-type; this spec hardcodes no model IDs."
- **§5 classification:** "`rate_limit` → `quota_exhausted` (+ reset time when present), `refusal` → `policy_block`, auth errors → `auth_failure`… **Account-level failures emit plain stderr with no JSON envelope — classified by stderr match, never filed as parse errors**, or the re-auth/quota alerts never fire. `error_max_budget_usd` maps to `agent_failure` (it is a CLI-side budget, not provider quota)."
- **§5 usage-reader duty:** "(a) in-band limit warnings/blocks → `exhausted_until` + reset time — reliable, load-bearing; (b) per-run token/cost fields from the JSON envelope → ledger input; (c) `/usage`-class utilization data **if** it proves script-readable — de-risked by an early implementation spike, explicitly not load-bearing for the milestone."
- **§3.3.1:** "Runners are DB-blind — file in (`task.json`), files out (`result.json`, `log.jsonl`), exit code." `runner/` and `providers/` must not import `db/` (import-linter already enforces the layering).
- Layer contract (already enforced): `app → api → orchestrator → {github|observe|quota|runner} → providers → {config|contracts|db} → domain`. So `runner/` may import `providers/`, `contracts/`, `config/`, `domain/` — **not** `db/`… *(correction: `db` sits in the same layer group as `config|contracts`, so `runner → db` is permitted by the layer contract. The DB-blindness rule is about the **runner container**, not the `runner/` package; the package legitimately never needs `db` and must not acquire it — enforced by an added `forbidden` contract, see Task A0.)*

## The empirical CapAdd floor (SPEC §4.2 / [CD§2.4(ii)]) — executed 2026-08-01

SPEC defers this to "one-afternoon empirical test during implementation (root + CapDrop=ALL, add caps only on observed failure) and then locked by the create-body test." **Executed against Docker CE 29.6.2 on `rockylinux/rockylinux:10`, adding one capability per observed failure:**

| Round | Caps | Observed failure |
|---|---|---|
| 1 | `CapDrop=ALL` only | `dnf install git` fails: `cpio: open failed`/`symlink failed - Permission denied` unpacking rpms |
| 2 | `+DAC_OVERRIDE` | dnf OK; `chown` → EPERM; `runuser` → "cannot set groups" |
| 3 | `+CHOWN,SETUID,SETGID` | `runuser` OK; `chmod` on a foreign-owned file → EPERM |
| 4 | `+FOWNER` | chmod OK; cross-uid `kill` → EPERM |
| 5 | `+KILL` | kill OK; `dnf install httpd` fails: `cpio: cap_set_file failed` on `/usr/sbin/suexec` |
| 6 | `+SETFCAP` | **all green**: dnf (git/node/httpd), `npm install -g`, uv install + venv, `useradd`, `runuser`, service start on **:80**, cross-uid tree-kill, chown+chmod |

**`NET_BIND_SERVICE` is deliberately absent and is not needed.** Verified directly: httpd binds `:80` and serves under the 7-cap set, because Docker sets `net.ipv4.ip_unprivileged_port_start=0` inside containers (confirmed by reading the sysctl in the probe). This retires [CD§2.3]'s "projects whose test suite needs to bind ports < 1024 will park" concern for the capable-box posture.

**Locked floor (7): `CHOWN, DAC_OVERRIDE, FOWNER, KILL, SETFCAP, SETGID, SETUID`** — SPEC's expected six plus **`SETFCAP`**, which SPEC did not anticipate and which any distro package shipping file capabilities (httpd/suexec, ping, dumpcap — the pilot needs tshark) requires. `AUDIT_WRITE` is deliberately **not** added: only `sudo`'s audit message fails, which is cosmetic inside a root container. Never added: `SYS_ADMIN`, `SYS_PTRACE`, `SYS_MODULE`, `NET_ADMIN`, `NET_RAW`.

**Caveat to record in the PR:** capability semantics are kernel-level and transfer, but this ran on Docker Desktop/WSL2, not Rocky 10 with SELinux enforcing. `install.sh` (T9) re-runs `scripts/capfloor.sh` on the VM as an install-time assertion; the `:Z`/`:z` labeling behaviour is only genuinely exercised there.

```python
"""The container-create body: a pure function of three enumerated components (SPEC §4.2).

Every field derives exclusively from Werft-owned state [CD M1]. No byte
originating in a managed repository or a run workspace is ever an input —
`runs.result` and `backlog_items.body` are agent-reachable, so this module
takes explicit **columns**, never rows.
"""

import os
from dataclasses import dataclass
from typing import Any

from pydantic import BaseModel, ConfigDict, Field

# Settled empirically against Docker CE 29.6.2 on rockylinux/rockylinux:10 —
# root + CapDrop=ALL, one capability added per observed failure. See scripts/capfloor.sh.
# SETFCAP is beyond SPEC §4.2's expected set: rpm restores file capabilities
# (httpd/suexec, dumpcap) and fails the whole transaction without it.
CAP_ADD_FLOOR: tuple[str, ...] = (
    "CHOWN", "DAC_OVERRIDE", "FOWNER", "KILL", "SETFCAP", "SETGID", "SETUID",
)

RUN_ROOT = "/srv/werft/runs"

BASE_HOST_CONFIG: dict[str, Any] = {
    "CapDrop": ["ALL"],
    "CapAdd": list(CAP_ADD_FLOOR),
    "SecurityOpt": ["no-new-privileges:true"],   # default seccomp: no entry at all
    "ReadonlyRootfs": False,                     # SPEC §4.2 — the capable-box decision
    "Privileged": False,
    "PidsLimit": 4096,
    "ShmSize": 1 << 30,                          # Chromium
    "Tmpfs": {"/tmp": "rw,nosuid,nodev,size=1g"},
    "PortBindings": {},
    "AutoRemove": False,                         # manager removes explicitly after reading outputs
}

# The per-run computed component. No other key may ever appear here (SPEC §4.2).
PER_RUN_KEYS: frozenset[str] = frozenset({"Name", "NetworkMode", "Dns", "Binds", "Labels"})

# The closed typed delta.
DELTA_KEYS: frozenset[str] = frozenset({"Memory", "NanoCpus"})


class CreateBodyError(Exception):
    """The body could not be built from Werft-owned state alone."""


class ProjectRunnerConfig(BaseModel):
    """Per-project delta — columns, not rows; ranges, not free values."""

    model_config = ConfigDict(extra="forbid", frozen=True)

    image_digest: str
    memory_bytes: int = Field(ge=2 << 30, le=32 << 30)
    nano_cpus: int = Field(ge=1_000_000_000, le=8_000_000_000)


@dataclass(frozen=True)
class RunPlacement:
    """Enumerated per-run facts, all manager-computed."""

    run_id: str
    container_name: str
    network_name: str
    dns_ip: str
    workspace_dir: str
    outputs_dir: str
    task_json_path: str
    secrets_dir: str


def _contained(path: str, run_id_dir: str) -> str:
    real = os.path.realpath(path)
    root = os.path.realpath(run_id_dir)
    if real != root and not real.startswith(root + os.sep):
        raise CreateBodyError(f"mount source {path!r} resolves outside the run directory {root!r}")
    return real


def build_create_body(
    placement: RunPlacement, config: ProjectRunnerConfig, *, entrypoint: list[str]
) -> dict[str, Any]:
    if "@sha256:" not in config.image_digest:
        raise CreateBodyError("image must be digest-pinned (SPEC §4.1); tags are rejected")

    run_dir = os.path.dirname(os.path.realpath(placement.task_json_path))
    workspace = _contained(placement.workspace_dir, run_dir)
    outputs = _contained(placement.outputs_dir, run_dir)
    secrets = _contained(placement.secrets_dir, run_dir)
    task_json = _contained(placement.task_json_path, run_dir)

    host_config = dict(BASE_HOST_CONFIG)
    host_config["Memory"] = config.memory_bytes
    host_config["NanoCpus"] = config.nano_cpus
    host_config["NetworkMode"] = placement.network_name
    host_config["Dns"] = [placement.dns_ip]
    host_config["Binds"] = [
        f"{workspace}:/work:rw,Z",       # private label — no other container may read it
        f"{outputs}:/outputs:rw,z",      # shared label — the manager reads it after exit (§4.3)
        f"{task_json}:/task.json:ro",
        f"{secrets}:/run/secrets:ro",    # a DIRECTORY, so token re-mint by rename is seen
    ]
    return {
        "Image": config.image_digest,
        "Entrypoint": entrypoint,
        "Cmd": [],
        "WorkingDir": "/work",
        "Labels": {"werft.run_id": placement.run_id},
        "HostConfig": host_config,
    }
```
*(`Name` is a query parameter on `POST /containers/create`, not a body key; `lifecycle.py` passes `placement.container_name` there — `PER_RUN_KEYS` names the component, and the test that enumerates it documents that fact.)*
