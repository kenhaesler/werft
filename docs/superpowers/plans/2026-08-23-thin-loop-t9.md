# T9 — Deploy: compose, install floors, egress activation, backup — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship the deployment layer (issue #26): the compose stack (postgres, manager-migrate, manager, egress-proxy, dns-guard, docker-socket-proxy), `install.sh` with every SPEC §2 floor asserted loudly, nightly pg_dump + restic backup — and the manager-side egress activation (per-slot run networks, squid/dns-guard attachment, per-run allowlists, proxy env) that turns T8's dormant evidence seam live.

**Architecture:** Static per-slot subnets (`10.90.<slot>.0/24`, lineage containment-design M6) keep squid's config static: the run network is created *with* an explicit IPAM subnet, and Docker's pool-overlap refusal is the durable slot lock (no migration, no new column). squid and dns-guard are hot-attached to each run network at fixed per-slot IPs (`.2`/`.3`); the driver writes the slot's `dstdomain` allowlist file and SIGHUPs squid. Everything is gated on `egress_slot_count > 0` — the default `0` preserves today's behavior byte-for-byte, so dev on Windows and every existing test stay green.

**Tech Stack:** Docker Compose; squid + dnsmasq built from Rocky base images (Werft-owned Dockerfiles, no new registry trust); `tecnativa/docker-socket-proxy` digest-pinned; bash for install/backup; systemd timers; restic; Python 3.14 manager changes under `manager/werft/`.

**Spec:** `SPEC.md` §2, §4.2, §4.5, §8, §10; issue #26; lineage citations in `docs/lineage/` (ARCHITECTURE-v1.4 §10.1/§10.6/§10.8, BUILD-PLAN P0.2/§15.1, containment-design M6/S1). The lineage-research extraction that grounds the D-decisions below was done 2026-08-23 against those files.

## Global Constraints

- Rocky Linux 10 host, SELinux **enforcing**; x86-64-v3 vCPU asserted at install (SPEC §2).
- Docker CE **≥ 29.6.2, and never 29.4.2** (BUILD-PLAN §15.1 C1); bundled containerd version verified at install.
- Kernel floor covering CVE-2026-31431 (KEV) asserted; `{"selinux-enabled": true}` in `daemon.json` and asserted effective via `docker info` (arms Docker's LSM mitigation).
- PostgreSQL 18.x latest minor, digest-pinned, volume at `/var/lib/postgresql` — **never** the pre-18 `/data` path (SPEC §2; the alpine entrypoint silently re-inits on the old path).
- Secrets are file mounts, never env (SPEC §10). Zero public listeners; manager port bound to the Tailscale IP only; firewalld drops non-tailnet (SPEC §10).
- All images referenced by compose are digest-pinned or Werft-built; the create-body already rejects tags for runner images.
- Manager code: Python 3.14, ruff + import-linter gates, pytest baseline must be `baseline + new`, zero lost. POSIX-only tests carry `skipif(sys.platform == "win32")`.
- No agent-authored bytes in any image build [CD M4].
- `manager/werft/` layering: `config` and `runner` cannot import `orchestrator`; `orchestrator` is the composition layer (import-linter enforces).
- Egress activation is **opt-in by config**: `egress_slot_count = 0` (default) must leave every current behavior unchanged.

## D-decisions (argued, for the PR body)

- **D1 — Slot = subnet, lock = Docker.** Lineage M6 demands static per-slot subnets so squid's ACLs stay static and `Dns` stays enumerable. We keep per-run network *names* (`werft-net-{run_id}`, re-adoption unchanged) but create each with IPAM subnet `10.90.<slot>.0/24`. Docker refuses overlapping pools, so "create succeeded" *is* the slot claim, durable across manager crashes (the network outlives us; the existing sweeps already remove dead runs' networks, which frees the slot). No `runs.slot` column, no migration.
- **D2 — Per-run ACLs without a manager-shaped SPOF.** squid.conf is static and enumerates N slot ACL pairs: `acl slotK_src src 10.90.K.0/24` + `acl slotK_dst dstdomain "/etc/squid/allow/slotK.txt"`. The driver writes the slot file (atomic rename) and SIGHUPs squid through the *existing* `kill_container(signal=...)` path. If the HUP fails, the run proceeds with the previous slot allowlist and the failure is logged — degraded egress is a logged incident, never a parked run. Teardown truncates the file and HUPs again (best-effort).
- **D3 — RFC1918/private destinations denied ahead of the allowlist** (SPEC §4.5 mandates what lineage S1 only suggested): `10/8, 172.16/12, 192.168/16, 169.254/16, 100.64/10, 127/8` as `dst` deny before any allow.
- **D4 — Explicit proxy, no bump, no intercept.** Runners get `HTTP_PROXY`/`HTTPS_PROXY`/`http_proxy`/`https_proxy` = `http://10.90.<slot>.2:3128` and `NO_PROXY=localhost,127.0.0.1` in the container env (per-run computed component — key-enumerated, D1 makes the values slot-static). In explicit-proxy mode squid matches `dstdomain` on the CONNECT hostname — no `ssl_bump`, no CA, subscription-CLI TLS untouched. A tool that ignores proxy env still has no route: the network stays `Internal: true`.
- **D5 — dns-guard is dnsmasq, allowlist-mirrored, logged, bounded.** `no-resolv`, explicit `server=/domain/1.1.1.1` per allowed domain (generated from werft config by a deploy-time script), `address=/#/` NXDOMAIN catch-all, `log-queries=extra` to a bind-mounted file, `dns-forward-max=64` as the honest available bounding knob (dnsmasq has no true QPS limiter; stated, not hidden). **Not** started with `bind-interfaces` (it must answer on hot-attached interfaces — lineage M6 audit note).
- **D6 — Registry presets, closed vocabulary.** `ProjectDispatch` gains `registries: list[str]` (preset names: `npm`, `pypi`, `dnf-rocky`, `crates`, `go`) and `extra_hosts: list[str]` (literal hostnames). Presets expand to host lists in code (SPEC §4.5's own examples). `extra="forbid"` already refuses typos. Slot allowlist = BASE_ALLOW (github + provider hosts) ∪ preset expansion ∪ extra_hosts.
- **D7 — Same-path bind mounts.** The manager container mounts `/srv/werft:/srv/werft` and `/opt/werft/config:/opt/werft/config:ro`. Mount *sources* in runner create-bodies are host paths handed to the daemon; identical in-container paths mean the existing path-construction code needs zero awareness of being containerized.
- **D8 — The T8 seam activates by configuration only.** squid logs to `/srv/werft/egress/log/squid/access.log`, dnsmasq to `/srv/werft/egress/log/dnsguard/queries.log` (both bind mounts); compose sets `WERFT_SQUID_ACCESS_LOG`/`WERFT_DNS_GUARD_QUERY_LOG` to those paths. `extract_egress_lines` and the collector are already format-agnostic and subnet-filtered — no code change.
- **D9 — Backup excludes the GitHub App key.** It is re-creatable from GitHub in minutes and is the one fleet-wide credential; lineage flags the choice and we take the exclusion arm. Everything else under `/opt/werft/{compose,config}` plus dumps plus `/srv/werft/runs` goes to restic (transcripts offsite is SPEC §8's accepted risk #4). Retention 14 daily + 8 weekly; nightly systemd timer on the *host* (works when the stack is broken); monthly restore drill with ntfy on failure.
- **D10 — Squid/dnsmasq images are Werft-built from the same Rocky base as the runner image.** No new upstream trust beyond what T-earlier already established (Rocky org image, digest-pinned); postgres and tecnativa/docker-socket-proxy are pulled digest-pinned.
- **D11 — DockerClient grows `tcp://` support** because compose puts the daemon behind `tcp://docker-socket-proxy:2375`. httpx does TCP natively; the unix-socket transport stays the default.
- **D12 — Floors are functions, tested with stubs.** `deploy/install/floors.sh` is a sourceable library of `assert_*` functions; `install.sh` drives it. A Linux-only pytest module stubs PATH commands and proves **each** floor fails loudly (exit ≠ 0, names the floor) and passes when satisfied — that is the "every floor assertion fails loudly when violated" acceptance, executable in CI.
- **D13 — Two invented numbers, flagged for operator veto:** `CONTAINERD_FLOOR` and `KERNEL_FLOOR` concrete values must be resolved by the implementer at execution time (moby bundled-containerd for 29.6.2; Rocky 10 advisory kernel for CVE-2026-31431) and stated in the PR body with their sources. The plan deliberately does not invent them.

## Scope boundaries (what T9 does NOT build)

- **No live-agent test in CI.** The full-agent acceptance (real run, real fetch, fetch line appears in collected egress evidence) requires the VM, the GitHub App, and the Claude credential — it is the RUNBOOK's executed acceptance, performed by the operator, recorded in the PR.
- **No per-slot DNS filtering.** dns-guard's allowlist is the union across projects (generated at deploy). Per-slot DNS views are post-milestone; squid still gates every connection per-slot.
- **No auto-GC, no log rotation service.** squid's own `logfile_rotate 2` bounds the access log; dnsmasq `log-facility` file is bounded by the nightly backup script's size check (alert, not rotate).
- **No `local-inference` service** (lineage optional; deferred with the local tier, SPEC §11).
- **No promotion of `max_concurrent_runs` to slots.** Boot refuses `max_concurrent_runs > egress_slot_count` when egress is enabled; that is the whole coupling.

```python
REGISTRY_PRESETS: dict[str, tuple[str, ...]] = {
    "npm": ("registry.npmjs.org",),
    "pypi": ("pypi.org", "files.pythonhosted.org"),

_HOSTNAME = re.compile(r"^(?=.{1,253}$)[a-z0-9]([a-z0-9-]*[a-z0-9])?(\.[a-z0-9]([a-z0-9-]*[a-z0-9])?)+$")
```

`ProjectDispatch` gains:

```python
    #: SPEC §4.5: the project's declared registry set, by preset name — werft
    #: config, never repo config. Expanded by `egress_hosts()`.
    registries: list[str] = Field(default_factory=list)
    #: SPEC §4.5: "the project's declared extra hosts" — literal hostnames.
    extra_hosts: list[str] = Field(default_factory=list)

    @field_validator("registries")
    @classmethod
    def _known_presets(cls, value: list[str]) -> list[str]:
        unknown = [r for r in value if r not in REGISTRY_PRESETS]
        if unknown:
            raise ValueError(f"unknown registry preset(s) {unknown!r}; known: {sorted(REGISTRY_PRESETS)}")
        return value

    @field_validator("extra_hosts")
    @classmethod
    def _hostname_shaped(cls, value: list[str]) -> list[str]:
        for host in value:
            if not _HOSTNAME.match(host.lower()):
                raise ValueError(f"extra host {host!r} is not a bare hostname")
        return value

    def egress_hosts(self) -> list[str]:
        hosts: set[str] = set()
        for preset in self.registries:
            hosts.update(REGISTRY_PRESETS[preset])
        hosts.update(h.lower() for h in self.extra_hosts)
        return sorted(hosts)
```

### Task 6: Driver — slot-claiming network create, attach, allowlist, teardown

**Files:**
- Modify: `manager/werft/orchestrator/driver.py`, `manager/werft/orchestrator/sweeps.py`
- Test: `manager/tests/integration/test_egress_activation.py` (new; reuse `manager/tests/fakes.py` — extend the fake Docker client with connect/disconnect/subnet recording)

**Interfaces (consumed):** Tasks 1–5. **Produces:** behavior only.

Behavior spec (the test list below is the contract):

1. **Off (`egress_slot_count == 0`)**: `_prepare_and_launch` calls `create_network(name)` exactly as today (no subnet kwarg), placement `proxy_url == ""`, `dns_ip == settings.runner_dns_ip`, no connect, no allowlist write, no HUP. Every pre-existing dispatch/driver/sweep test passes unmodified.
2. **On (`egress_slot_count = N > 0`)**: before container create, the driver tries slots in order `0..N-1`: `create_network(name, subnet=slot_subnet(k))`; on `is_pool_overlap` → next slot; all N taken → treat as a transient dispatch failure (raise the same retryable error class the driver uses for daemon failures — the run returns to the queue with backoff, never parks). On success:
   - `connect_network(net, settings.egress_proxy_container, ipv4=slot_squid_ip(k))` and `connect_network(net, settings.dns_guard_container, ipv4=slot_dns_ip(k))`. A failure here tears the network down and is the same transient failure (a missing egress-proxy container must not park runs).
   - `write_allowlist(allow_dir, k, entry.egress_hosts())` then `kill_container(settings.egress_proxy_container, signal="HUP")` — HUP failure: log `egress.allowlist_reload_failed`, continue (D2).
   - Placement built with `dns_ip=slot_dns_ip(k)`, `proxy_url=f"http://{slot_squid_ip(k)}:{settings.egress_proxy_port}"`.
3. **Re-adoption**: derive the slot from the adopted network's subnets (`subnets_of(inspect_network(...))` → parse `{prefix}.K.0/24`); when derivable, rebuild placement with the slot's dns/proxy values; when not (egress off at claim time), fall back to off-mode placement. No allowlist rewrite on re-adoption (the file is already the run's).

```bash
#!/usr/bin/env bash
# Werft install floors (SPEC §2, BUILD-PLAN P0.2). Each assert_* is standalone
# and stub-testable: it consults only $PATH commands and readable files.
set -u

# Dated floor pins (BUILD-PLAN §15.1: floors are policy, values re-checked dated).
DOCKER_FLOOR="29.6.2"          # C1; and 29.4.2 is refused outright below
DOCKER_REFUSED="29.4.2"
CONTAINERD_FLOOR="RESOLVE"     # D13: bundled containerd of ≥29.6.2 — resolve at execution
KERNEL_FLOOR="RESOLVE"         # D13: Rocky 10 advisory kernel for CVE-2026-31431 — resolve at execution

_fail() { echo "FLOOR FAIL $1: $2" >&2; return 1; }
_vergte() { [ "$(printf '%s\n%s\n' "$2" "$1" | sort -V | head -1)" = "$2" ]; }

assert_x86_64_v3() {
    local out
    out=$(/lib64/ld-linux-x86-64.so.2 --help 2>/dev/null | grep -F 'x86-64-v3')
    case "$out" in *"(supported"*) return 0 ;; esac
    _fail x86_64_v3 "CPU does not report x86-64-v3 (SPEC §2; default qemu64 fails this)"
}

assert_docker_version() {
    local v
    v=$(docker version --format '{{.Server.Version}}' 2>/dev/null) \
        || return $(_fail docker_version "docker daemon unreachable")
    [ "$v" = "$DOCKER_REFUSED" ] && return $(_fail docker_version "$v is refused (C1 trap release)")
    _vergte "$v" "$DOCKER_FLOOR" || _fail docker_version "$v < floor $DOCKER_FLOOR"
}

assert_containerd_version() {
    local v
    v=$(containerd --version 2>/dev/null | awk '{print $3}' | tr -d v) \
        || return $(_fail containerd "containerd not found")
    _vergte "$v" "$CONTAINERD_FLOOR" || _fail containerd "$v < floor $CONTAINERD_FLOOR"
}

assert_kernel_floor() {
    local v; v=$(uname -r)
    _vergte "$v" "$KERNEL_FLOOR" || _fail kernel "$v < floor $KERNEL_FLOOR (CVE-2026-31431/KEV)"
}

assert_selinux_enforcing() {
    [ "$(getenforce 2>/dev/null)" = "Enforcing" ] || _fail selinux "getenforce != Enforcing"
}

assert_docker_selinux_enabled() {
    docker info --format '{{json .SecurityOptions}}' 2>/dev/null | grep -q selinux \
        || _fail docker_selinux "docker info lacks selinux SecurityOption (daemon.json selinux-enabled)"
}

assert_workspace_mount() {
    local opts fstype
    fstype=$(findmnt -no FSTYPE --target /srv/werft 2>/dev/null) \
        || return $(_fail workspace_mount "/srv/werft not on a mount")
    [ "$fstype" = "xfs" ] || return $(_fail workspace_mount "fstype $fstype != xfs")
    opts=$(findmnt -no OPTIONS --target /srv/werft)
    case "$opts" in *prjquota*|*pquota*) : ;; *) return $(_fail workspace_mount "no pquota in [$opts]") ;; esac
    case "$opts" in *nosuid*) : ;; *) return $(_fail workspace_mount "no nosuid") ;; esac
    case "$opts" in *nodev*)  : ;; *) return $(_fail workspace_mount "no nodev")  ;; esac
}

assert_firewalld_posture() {
    [ "$(firewall-cmd --state 2>/dev/null)" = "running" ] \
        || return $(_fail firewalld "firewalld not running")
    local dz; dz=$(firewall-cmd --get-default-zone)
    [ "$dz" = "drop" ] || return $(_fail firewalld "default zone $dz != drop")
    firewall-cmd --zone=trusted --list-interfaces | grep -qw tailscale0 \
        || _fail firewalld "tailscale0 not in trusted zone"
}

assert_tailscale_up() {
    tailscale ip -4 >/dev/null 2>&1 || _fail tailscale "tailscale not up"
}

run_all_floors() {
    local rc=0 f
    for f in assert_x86_64_v3 assert_docker_version assert_containerd_version \
             assert_kernel_floor assert_selinux_enforcing assert_docker_selinux_enabled \
             assert_workspace_mount assert_firewalld_posture assert_tailscale_up; do
        "$f" || rc=1
    done
    return $rc
}
```

`werft-backup.sh` (host-side, root; must work when the manager is broken — only postgres needs to be up for the dump half, and restic still pushes the previous dump if it isn't):

```bash
#!/usr/bin/env bash
# Nightly Werft backup (SPEC §2/§10; lineage §10.6): pg_dump -Fc + restic offsite.
# Retention 14 daily + 8 weekly. D9: the GitHub App key is EXCLUDED (re-creatable).
set -euo pipefail
COMPOSE=/opt/werft/compose/compose.yaml
DUMPS=/opt/werft/backups/dumps
NTFY_URL_FILE=/opt/werft/secrets/ntfy_url        # optional; alert on failure
export RESTIC_REPOSITORY_FILE=/opt/werft/secrets/restic_repo
export RESTIC_PASSWORD_FILE=/opt/werft/secrets/restic_password

notify() {
    [ -r "$NTFY_URL_FILE" ] || return 0
    curl -fsS -m 10 -d "$1" "$(cat "$NTFY_URL_FILE")" >/dev/null || true
}
trap 'notify "werft-backup FAILED on $(hostname): line $LINENO"' ERR

mkdir -p "$DUMPS"
if docker compose -f "$COMPOSE" exec -T postgres pg_isready -U werft -d werft >/dev/null 2>&1; then
    docker compose -f "$COMPOSE" exec -T postgres \
        pg_dump -Fc -U werft werft > "$DUMPS/werft-$(date +%F).dump.tmp"
    mv "$DUMPS/werft-$(date +%F).dump.tmp" "$DUMPS/werft-$(date +%F).dump"
    ls -1t "$DUMPS"/werft-*.dump | tail -n +15 | xargs -r rm --   # local dumps: keep 14
else
    notify "werft-backup: postgres down; pushing previous dumps only"
fi

restic backup \
    --exclude /opt/werft/secrets/github_app_key \
    "$DUMPS" /opt/werft/compose /opt/werft/config /srv/werft/runs
restic forget --keep-daily 14 --keep-weekly 8 --prune
```

`werft-restore-drill.sh`: throwaway `docker run --rm` postgres container (same digest via `$POSTGRES_IMAGE` sourced from `/opt/werft/compose/.env`), `pg_restore` the newest dump into it, canary query `SELECT count(*) FROM runs;` must return ≥ 0 rows without error, `SELECT count(*) FROM alembic_version;` must return 1; ntfy on failure, ntfy a one-line success ("restore drill OK, N runs") on success — a backup that has never been restored is not a backup.

Units: `werft-backup.timer` `OnCalendar=*-*-* 03:30`, `Persistent=true`; `werft-restore-drill.timer` `OnCalendar=monthly`, `Persistent=true`; services `Type=oneshot`, `ExecStart` the scripts from `/opt/werft/compose/backup/` (install.sh copies `deploy/` there and `systemctl enable --now` both timers).
