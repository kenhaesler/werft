## Global Constraints

**SPEC governs; lineage is compressed history.** Where `docs/lineage/` conflicts with SPEC.md v1.0, SPEC wins. One place where **SPEC conflicts with itself** — resolved here, loudly, so nobody "fixes" it backwards mid-implementation:

> **The `administration` permission decision.** SPEC §6.3 states an App permission ceiling of "administration read" (inherited verbatim from lineage [A§8.6], where a *human* ran `werftctl onboard` with a short-lived PAT and the manager never touched protection). But the realignment moved onboarding **and the automatic flip** into the manager (SPEC §3.1: "The flip applies the strict branch protection in the same action"; §9: "project onboard/flip" API; §6.3: "the manager applies the strict required-check protection"). GitHub's permissions matrix is unambiguous: `PUT /repos/{o}/{r}/branches/{branch}/protection` requires **Administration: write**; read only covers GET (verified 2026-08-03, docs.github.com permissions-required-for-github-apps). The flip is automatic-on-green with no human in the path, so the PAT flow cannot serve it. **Resolution: the App holds `administration: write`; the ceiling line in SPEC §6.3 is the bug** (SPEC's own header allows this: where it conflicts with doctrine, SPEC has a bug — and doctrine demands the flip). Mitigations kept: runner tokens stay attenuated to `contents: write` on one repo (§4.4 — `administration` never enters a runner); the manager mints its *own* ops tokens without `administration` and mints a **separate, transient, admin-only token** for each protection call, revoked immediately after. This divergence is flagged in the T5 PR body for the operator's veto.

## Behavioral decisions (locked here so tasks don't re-litigate)

1. **Terminal cleanup, spec-literal:** on `→ canceled` with a PR: close PR + delete `werft/run-<id>`; on `→ merged`: delete branch (idempotent — GitHub may have auto-deleted). `parked` keeps PR + branch (parked always admits requeue; a future dispatch force-resets the branch; bootstrap projects have no CI to burn and Werft never update-branches non-merging PRs, so no zombie CI churn).
2. **ci_timeout epoch** = `created_at` of the latest `run_events` row with `event_type='status_changed'` and `payload->>'to' = 'awaiting_ci'` (the trigger writes it; no new column).
3. **CI-red bookkeeping:** the latest `run_attempts` row (outcome NULL — "pending oracle") gets `outcome='ci_red'`; then `attempt_count < max_attempts` → `awaiting_ci→queued` (fresh dispatch), else `awaiting_ci→parked` (`parked_reason='ci_red'`). Green fills `outcome='ci_green'` at the `awaiting_ci→merging` CAS.
4. **Flip observation site:** the 30 s check poller also scans `awaiting_review` runs of **bootstrap** projects for a green `werft-oracle` on the PR head (the workflow lands via the PR that creates it and runs on that same PR). The flip mutates the **project only** (guarded `UPDATE … WHERE lifecycle='bootstrap'`), applies strict protection, writes `project_events` (`lifecycle_flipped`, `protection_applied`), alerts. The observed run stays `awaiting_review` — it was dispatched under bootstrap rules and still needs the operator's accept.
5. **Bootstrap accept-merge and the async 202:** GitHub's update-branch is async, so "update-branch + immediate squash-merge" is implemented as a tick-driven decision table on the `merging` state (each pass is short-lived and crash-safe, satisfying "no sleeping coroutines"): `mergeable_state == 'behind'` → update-branch (head guard), stay `merging`; `mergeable == false` (dirty) → `parked/merge_blocked` (SPEC §6.2's named reason for the bootstrap conflict); otherwise squash-merge with head-sha guard; merge 409 (external base move — rare) → stay `merging`, next tick retries (equivalent-or-better than "retry once": bounded in practice, never converts accept into a CI wait, and each retry is guard-protected). `mergeable == null` → stay `merging` (computing; next tick).
6. **oracle_gated merging:** arrived-from-green. Try squash-merge (head guard) directly: 200 → `merged` (+`merge_commit_sha`, delete branch); 405 + dirty → `parked/merge_conflict`; 405 + behind/blocked → update-branch → `merging→awaiting_ci` (the updated head must re-earn green — SPEC §6.2); 409 → `merging→awaiting_ci`; null mergeable → stay.
7. **Requeue resets budget:** operator requeue (`parked→queued`) sets `attempt_count=0`, `next_attempt_at=now()` — a human explicitly granted a fresh budget; without the reset a budget-spent run would re-park instantly and requeue would be a lie.
8. **Failed-state advance (thin):** latest attempt outcome `quota_exhausted` → `failed→blocked_quota` (`next_attempt_at = exhausted_until` when known, else now+15 min; T7 refines with window headroom); outcome in `BUDGET_EXEMPT_OUTCOMES` never increments the genuine-failure meaning of `attempt_count`; `attempt_count >= max_attempts` → `failed→parked`; else `failed→queued` with backoff `min(2^attempt_count × 30 s, 30 min)`. `blocked_quota→queued` wake is a generic tick sweep (`status='blocked_quota' AND next_attempt_at <= now()`).
9. **Alert seam:** `observe/alerts.py` defines the `AlertSink` protocol + `NullAlertSink` in T5 (handlers call it); T6 ships `NtfyAlertSink`. Methods: `review_waiting(project_slug, run_id, pr_url)`, `run_parked(project_slug, run_id, reason)`, `project_flipped(project_slug)`, `auth_failure(provider)`, `quota_exhausted_until(provider, until)`, `disk_threshold(percent)` — the last two are invoked by T7/T8 at their natural sites; the sink ships complete now. Sinks **never raise** (alerting must not break the loop).
10. **Intake:** eligible backlog items of non-paused projects with no live run get a `queued` run via `INSERT … ON CONFLICT DO NOTHING` against `ux_runs_one_active_per_item`. `runs.provider` stays NULL at intake (the claim transaction picks it — T7).
11. **Error mapping:** `github/` raises `GitHubApiError(status, message)` (subclass `GitHubUnavailable` for transport errors / 5xx / rate-limit with retry-after). Handlers map: unavailable → leave state, next tick retries (the tick is the retry mechanism — no inline sleeps); 404 on load-bearing objects (PR/repo gone) → the state machine's infra edge (`awaiting_ci→failed`, `awaiting_review→failed`); 422 on PR-open → adopt path, and if adoption finds nothing → `PermanentError` → park.
12. **API auth fail-closed:** no configured token file ⇒ every `/api/v1` request → 403 "api token not configured". Missing/wrong bearer → 401. `/healthz` stays open (the watchdog needs it).
13. **Event vocabulary:** add `"cleanup"` to `RUN_EVENT_TYPES` in `domain/events.py` (terminal PR/branch cleanup writes a `run_events` row). `ci_observed` rows are written on every decisive oracle observation (green/red) with payload `{sha, conclusion}`.
